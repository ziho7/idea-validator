## Material skill ambiguity observed

The skill explicitly permits analyzing supplied materials when browsing is unavailable, but its evidence contract requires a nonempty original HTTP(S) URL and one of `full`, `partial`, `snippet`, or `unavailable`. It has no explicit provenance/access state for a user-supplied summary or synthetic fixture without URLs. Inline tables are required to contain equivalent information, while `snippet`/`unavailable` records must have `stance: context`. This makes an offline summary with a directly supplied recurring behavior difficult to represent consistently: Case B can support a hypothesis *within the supplied synthetic scenario*, yet strict snippet treatment permits only background context. Both actual responses therefore transparently use human-readable unknown URL/access descriptions and scenario-qualified conclusions rather than pretending to be validator-ready ledgers. A schema-valid substantial offline ledger would currently require omitting the evidence entirely or inventing a URL; inventing URLs is unacceptable.

Suggested narrow clarification: allow `url: null` for explicitly marked user-supplied material; add provenance such as `user_supplied_summary` and `synthetic`; separate “supports the scenario claim as supplied” from “verified source evidence.” Make clear that conclusions based on supplied summaries are conditional, and that they do not count as inspected original pages or verified real-world user experiences. No skill files were edited.

No other material failure was observed in this bounded smoke check. The core guidance successfully prevented market transfer, duplicate counting, promotion-as-demand, feature-absence inference and manufactured payment conclusions.


## Remediation

Before v0.1.0 publication, the workflow and evidence/report references were amended: URL-less supplied materials use a labeled table, missing values remain unknown, synthetic evidence only supports scenario-conditional reasoning, and the JSON contract is explicitly scoped to web-source ledgers. No URLs should be invented to satisfy export requirements.
